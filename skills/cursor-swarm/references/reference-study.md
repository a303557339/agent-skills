# 参考站的机制与可迁移实现

参考：[califa / swarm-site](https://califa.github.io/swarm-site/)。公开仓库为 [GitHub](https://github.com/califa/swarm-site)，观察依据包括实际页面及其公开 [JavaScript bundle](https://califa.github.io/swarm-site/assets/index-BcWSe1v5.js) 和 [样式](https://califa.github.io/swarm-site/assets/index-DaDOAYTB.css)。构建资源文件名可能随原站更新而改变。

## 原站观察

页面先以约 18 个光标围绕中心运行。向下滚动或真实指针进入光标群，可以触发绘制。施工范围随向下滚动推进；任务携带依赖关系，多个光标同时工作，数量和节奏随待办任务与滚动速度变化。所有施工完成后，光标聚集为约 36 个的跟随群。

施工空档也有明确行为：空闲光标独立移动、停顿、寻找下一处工作，部分从边缘离场。新工作出现时再补充人员。观察一屏做完但整页尚未完成的时段，最容易区分这种四处游走的工作状态和最终围绕真实鼠标的群体跟随。

“绘制页面”有明确的动作语义：路径逐点描绘，矩形从起点向对角拖出，文字逐步输入，选区显示控制点和尺寸。原站还表演字号调整、辅助线吸附、复制组件和编辑文本，光标形状随任务切换。它使用专门的场景描述和设计坐标，并非给任意网页加一个鼠标 CSS 样式。

跟随是群体运动而非等距拖尾。每个光标围绕目标产生切向运动和径向修正，参考邻居速度，离群时加速追赶，在真实指针附近避让。朝向跟随速度平滑旋转；没有指针输入时，群体仍有自主运动。

## 此 skill 的实现取舍

保留聚集、群体工作、分散游走和最终成群跟随。附带的 `swarm-motion.mjs` 独立实现群体运动，`swarm-choreography.mjs` 提供方向不同的飞行、精确拖拽与非匀速输入轨迹，`cursor-swarm.mjs` 将真实 DOM 元素转换为施工目标，通过测量、裁剪、SVG 描线与装饰覆盖层呈现动作。

针对“群体工作后会四处移动”的体验，通用实现明确分离工作、待命和最终聚群：默认动态招募；按工作区域、距离和参与公平性派发；光标完成接近、按下、施工、检查、撤离整套动作。可见区域做完后，多余工人离场，少量工人独立游走；全页完工才进入鼠标跟随。输入节奏按完整字符分段，文本工具与插入点分开，避免所有工人都像同一条进度动画。

这些机制避免早先“固定少数工人 + 大量光标提前抱团跟随”的视觉割裂。可迁移版本的任务数量取决于真实 DOM，不会与原站的场景任务数量一一对应；调参时应比较具体工作与移动行为，不能只比较光标总数或截图。

目标页面继续使用自己的布局和语义。文字原文不被逐字替换，按钮、链接、表单依然是原控件，响应式规则由原页面决定。光标效果的坐标来自实时 DOM 测量，不要求目标页面适配原站的固定设计画布。

因此，本 skill 不复制原站的营销内容或整套场景，也不模拟任意设计软件中的全部编辑行为。复制组件、辅助线吸附等额外表演需要面向具体页面的显式编排。`text`、`rect`、`path`、`reveal` 是默认可迁移的任务种类。

另外补上了可复用网页效果需要的生命周期：卸载恢复、字体／尺寸变化后测量、动态内容刷新，以及减少动态效果和触屏默认降级。

## 如何对照

在原站观察开场、触发、施工、当前区域做完后的等待、滚动和完工跟随，再在本地 `/demo/` 完成相同操作。重点比较动作与状态切换：是否多个光标真实对应各自目标；文字和轮廓是否随着施工出现；做完一处后是否有检查和移开动作；空闲光标是否独立走动；新区域是否招募工人；全页完成后是否追赶和重新聚合。

效果相似度需要浏览器实际观察。结构检查和物理单元测试只能证明部分行为，不等于逐像素视觉一致；交付说明应分别报告已观察效果、测试结果与保留差异。
